# LeadOS — Leadership Operating System · v22.0 (Session-20 build)

A single-file, offline-first operating system for a leader **of team leads** — especially a new one. Vanilla JavaScript. No framework, no backend, no accounts, no APIs, no OAuth, no credentials, no build step, **no network dependency at all** (icons are inline SVG; fonts are system fonts; styling is an inline `<style>` tag; it runs from a double-clicked file). The entire application is `index.html`; all state lives in `localStorage`.

Open `index.html` in a browser. That is the whole install. First boot seeds a deliberately tense example org so every instrument is visibly live; set yourself (`#/data` → identity), then erase the example when your real org arrives.

3. **Promotion is gated, not congratulatory:** ≥2 dated evidence notes in 90d **and** zero re-absorption events in 30d, with refusals printing their reasons (t38). _Why:_ a ladder you climb by vibes is an org chart with extra steps; evidence is the only currency promotion accepts.
4. **Re-absorption decay is exact arithmetic (t39):** `2×(full cadences overdue) + 3×(below-level escalations, 60d) + 3×(times you did the holder's work, 60d) + 1×(evidence silence >30d)`; fires sev1 at ≥4 with every term printed. _Why:_ trust comes from transparent reasoning; a decay score you cannot recompute by hand is astrology.

Nine-box feeds candidates; ladder L3+ items count as their development evidence. _Why:_ a bench without a dated development move is a wish list.

## The storage contract (full)

* **One lineage key, forever:** `leados.v6`. The record's `meta.v` is the truth; v:16 today.
* **Migrations:** `MIGS[1..15]` are ensure-steps (additive, non-destructive, trail-stamped). The exact per-version collection enumeration of v1–v12 was never published anywhere legible, so the honest mechanism is *ensure-shape per step* — never a pretense of knowing each historical shape.
* **RECOVERY:** on corrupt bytes or a newer record, the offending bytes are quarantined to a side key, the main key is left untouched, in-memory state is a blank that is **not saved**, and every route banners until the human decides at `#/data` (download the quarantine for inspection, or start clean).
* **Export/Import/Merge:** export is a full JSON dump (the only redundancy a localStorage app has). Import validates + migrates v1–v15 up, refuses junk byte-identically (t12), and parks the pre-import state in a side key. Merge re-mints every id and rewires every reference (`parties`, `seatId/personId/leadId/ownerId/holderId/from/to/caseId/srcId/goalId/who/by`) through one map, then re-runs the audits (t17).

## The v22 flagship: `#/deleg` + bench + protocol

* **Ladder:** L1 tell · L2 task+report · L3 consult-then-act · L4 act-and-inform · L5 full ownership. Each rung names who decides and the severity ceiling the holder owns without you (S0/S1/S2/S3/S4).
* **Instrument, not picture:** decay score with every term printed · promotion gate with printed refusals · stuck-at-rung detection (90d) · hoarding detection (you hold >1 low rung per team) · chair-question cross-feed from `#/load`.
* **Bench:** per-seat cover score with the arithmetic printed; stale development moves halve the weight at 90d; `bench-empty` is key-person exposure, not admin debt.
* **Protocol:** your latency SLOs on what travels up, with live breach math (`age − SLO` per row) and an honest acknowledge-up action.
