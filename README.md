# LeadOS — Leadership Operating System · v20.0 (Session-18 build)

A single-file, offline-first operating system for a leader **of team leads** — especially a new one. Vanilla JavaScript. No framework, no backend, no accounts, no APIs, no OAuth, no credentials, no build step, **no network dependency at all** (icons are inline SVG; fonts are system fonts; it runs from a double-clicked file). The entire application is `index.html`; all state lives in `localStorage`.

Open `index.html` in a browser. That is the whole install. First boot seeds a deliberately tense example org so every instrument is visibly live; set yourself (`#/data` → identity), then erase the example when your real org arrives.

## The storage contract (full)

- **One lineage key, forever:** `leados.v6`. The record's `meta.v` is the truth; v:14 today.
- **Migrations:** `MIGS[1..13]` are ensure-steps (additive, non-destructive, trail-stamped). Honest note, kept from Session 17: the exact per-version collection enumeration of v1–v12 was never published anywhere legible, so the honest mechanism is *ensure-shape per step* — never a pretense of knowing each historical shape. Unknown keys survive the guard-spread and are *enumerated* by the `foreign-keys` audit so preservation is a choice, not a leak.
- **RECOVERY:** on corrupt bytes or a newer record, the offending bytes are quarantined to a side key, the main key is left untouched, in-memory state is a blank that is **not saved**, and every route banners until the human decides at `#/data` (restore from shelf download, or start clean).
- **Export/Import/Merge:** export is a full JSON dump (sealed cases included — your data, marked; the only redundancy a localStorage app has). Import validates + migrates v1–v13 up, refuses junk and future records **byte-identically** (t12), and parks the pre-import state in a side key. Merge re-mints every id and rewires every reference (`links`, `scope`, `parties`, `goalId`, `personId/leadId/ownerId/toId/fromId/caseId/srcId`) through one map, then re-runs the audits (t17).

## The flagship: `#/load`

- **Header:** meeting hours and % of your week · the verdict chip with its arithmetic · last measured energy (+ estimate labeling) · last purge age.
- **Self sparkline:** measured readings as a solid line, estimates as hollow dashed points; slope claimed only at n≥3 measured. The doctrine line is printed under the chart, because doctrine that's only in a log file gets forgotten.
- **Inventory table:** per-meeting cost, your seat (chair is the expensive one), review staleness vs purge cadence, verdict select, edit/kill/revive. Footer prints the full summation the cap rule uses — the advisory and the table can never disagree, because they share one computation.
- **Purge:** considers kill-verdicted, questioned, and stale meetings; kill-verdicted are deactivated (recoverable), the rest get fresh review stamps; the run is hashed into `purgeRuns` with hours freed. Quarterly, or the rule wakes.
- **Pace governor (home):** compares dated load (7d) against your last *measured* energy and says one of five honest sentences, components printed. Heuristic — labeled as such, never an order.

## The case spine (architectural core, summary)

Commit writes into every routed module in one transaction of the store, and every write lands in the propagation ledger with its route (visible on the home deck; audited by t04 on the ethics path).
