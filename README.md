# LeadOS pt-C — Data Visualization Engine

A React/TypeScript implementation of the **pt-C** brief: a pure SVG/Canvas
visualization layer (`LEADOS.viz`) — twelve chart types, a non-optional
source/confidence/label caption on every chart, full accessibility
fallbacks, and four pre-built dashboard compositions — with **zero
charting library and zero CDN dependency**.

> **This is not a port of a real `js/viz.js` from `github.com/wbweve/Leados`.**
> That file does not exist in the repository — verified this session via
> GitHub's Git Trees API (22 entries at `main`, no `js/` directory, no
> `viz` anywhere in the tree). The repository **is**, however, verified to
> be the same kind of project as this one (React 19 + Vite 7 + Tailwind 4 +
> `vite-plugin-singlefile`, confirmed by reading its `package.json` and
> `vite.config.ts` in full). See `AI-SESSION-LOG.md` §0 for the complete,
> line-by-line audit of what was and wasn't checked, and §1.2 for exactly
> how the brief's "framework-free `.js` files" description was reconciled
> with that verified React/Vite reality.

## Run it

```
npm install
npm run dev      # local dev server
npm run build    # outputs dist/index.html — a single, dependency-free file
npm run preview  # serve the production build locally
```

Open the app and use the top nav to switch between the chart **Catalog**
(all twelve types side by side) and the four dashboard compositions
(**Finance**, **People**, **Intelligence**, **Self**), plus a **Provenance**
tab with the live claim/status audit table.

## The non-optional data contract

Every chart (except the two listed in §2.6 of the session log — `Sparkline`
and `ScoreMath`, both explicitly described by the brief as compact/inline
elements, not full charts) is wrapped in `ChartFrame`, which:

- Renders `[source] · [confidence] · [label]` (+ `[caveat]` if present)
  below the chart, always, non-optionally.
- Wires `role="img"` + `aria-labelledby` to a `<title>`/`<desc>` pair inside
  the SVG (or an equivalent hidden pair for Canvas/DOM charts).
- Keeps a full `<table>` data fallback permanently in the DOM for screen
  readers, with a "Show as table" ↔ "Show as chart" toggle for sighted
  users.
- Lazily mounts the chart via `IntersectionObserver` (`useInView.ts`) —
  pure Web API, no library — so off-screen charts don't render.
- Encodes confidence redundantly: a colored dot in the caption, **and**
  dashed/50%-opacity rendering on the chart itself, never color alone.

## Changelog

### pt-C (this delivery)

- **Added** `src/viz/*` — twelve chart components implementing the full
  pt-C catalog as React components instead of the brief's literal
  `(data, options) → SVG string | Canvas element` functions — *why: the
  verified target repo and this sandbox are both React/Vite projects, not
  a loose-`.js`-files static site; re-expressing the brief's functions as
  components with an equivalent prop contract preserves every semantic
  requirement (purity, captions, confidence encoding) without pretending a
  framework-free module exists where none can.*
- **Added** `ChartFrame` + `useInView` as the shared chrome every chart
  shares — *why: the brief makes captions and accessibility fallbacks
  non-optional ("a chart without a caption is a claim without a source");
  centralizing them in one wrapper is the only way to guarantee no chart
  component can skip them.*
- **Added** `CalendarHeatmap` on `<canvas>`, all other charts on SVG — *why:
  directly follows the brief's stated ">100 points → canvas" performance
  rule; 364 cells crosses that threshold, nothing else in this build does.*
- **Rendered `CohortGrid` as a CSS grid, not canvas** — *why: the brief's
  own worked example is ≤16 cells, under its own stated canvas threshold;
  followed the stated rule over the illustrative example, and said so
  rather than silently picking one (see `AI-SESSION-LOG.md` §2.2).*
- **Rendered line-chart data gaps as a path break, not a visible dotted
  connector** — *why: drawing any line through a `null` value — dotted or
  not — implies a value exists between two real points, which conflicts
  with the brief's own repeated, stronger principle that no chart may
  imply more certainty than the data supports. The gap is omitted; the
  `null` is visible in the table fallback instead.*
- **Added** a fifth "Catalog" view beyond the four brief-named dashboards —
  *why: each named dashboard only exercises a subset of the twelve chart
  types; a catalog view was needed so every type has at least one fully
  captioned, inspectable instance.*
- **Used a `useState` tab bar instead of hash routing** (`#/finance` etc.
  kept only as doc comments) — *why: no real router/`ui.js` shell was read
  or verified to exist this session; building one from scratch was out of
  scope for a visualization-engine brief.*
- **Declined** to port any `engine.js`/`health.js`/`ui.js`/`playbooks.js`
  scoring/rule logic — *why: not read this session (budget); see
  `AI-SESSION-LOG.md` §0 row 6. `ScoreMath` uses the brief's own worked
  example instead of inventing a "real" computation.*
- **Labeled every sample dataset as fabricated**, in `src/viz/sampleData.ts`
  and in the app footer — *why: no real LeadOS event log was read this
  session; charts still need plausible `source:` strings to demonstrate
  the caption contract without overclaiming where the numbers came from.*
