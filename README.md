# LeadOS pt-L — Organizational Thermodynamics

A small React + Vite + Tailwind app that logs synthetic organizational events and applies **Shannon information
theory** to them: entropy of the event-type mix, a heuristic "mutual information" between two people's activity,
an information-bottleneck scan of the roster, and a findings-coverage signal-to-noise ratio.

> **Provenance note — read before trusting any claim about `github.com/wbweve/Leados`:** this build does **not**
> copy, fork, or continue that repository's code. This session fetched that repo directly via the GitHub REST
> Contents/Trees API (not just its README) and confirmed: (1) its root holds ~45+ loose, duplicate-named `.tsx`
> files alongside a separate, complete `src/` Vite+React+TypeScript tree; (2) the `src/` tree's own `App.tsx`
> only wires up `storage`, `circadian`, `fatigue`, `workers`, `types` — it does **not** import `src/lib/core.ts`,
> `src/lib/intelligence.ts`, or `src/lib/physics.ts`, which sit orphaned; (3) `src/lib/intelligence.ts` imports
> `{ engine, run }` from `./core`, but the real `src/lib/core.ts` exports no `engine` and no `run` — that import
> would not resolve; (4) no file, export, or string anywhere in the fetched tree matches `infoTheory`,
> `shannonEntropy`, `mutualInformation`, or `thermodynamics`. The pt-L brief's `LEADOS.infoTheory` module is
> therefore treated as an **unverified specification**, not real code, and nothing in this app is presented as a
> port of it. Full ledger in [AI-SESSION-LOG.md](./AI-SESSION-LOG.md) and in-app at **About / Provenance**.

## Run it

```
npm install
npm run dev       # local dev server
npm run build     # production build → dist/index.html (single file, inlined JS/CSS)
npm run preview   # preview the production build
```

`vite.config.ts` (already present in this template) uses `vite-plugin-singlefile`, so `npm run build` emits one
self-contained `dist/index.html`.

All data lives in **this browser's `localStorage`** under `leados-pt-l:events`. There are no network calls,
accounts, or servers. The roster and starting event log are synthetic, generated by a seeded PRNG
(`mulberry32`, fixed seed) so the numbers shown are reproducible.

## The Thermodynamics module (`src/lib/infoTheory.ts`)

Implements the pt-L brief's `LEADOS.infoTheory` as TypeScript against this app's own event model:

- **`shannonEntropy(events)`** — real Shannon entropy `H = −Σ p(x)·log2(p(x))` over the event-type distribution.
  The RIGID / ADAPTIVE / CHAOTIC interpretation bands are this delivery's own illustrative convention, not a
  validated threshold from any study — disclosed in the UI every time it's shown.
- **`mutualInformation(streamX, streamY, today, windowDays)`** — a weekly-binned, event-type co-occurrence
  heuristic between two people's logged activity. Labeled in its own output as *not* the rigorous channel-capacity
  mutual information of information theory proper.
- **`identifyBottlenecks(P, today)`** — flags people whose logged "information in" (events that reference them)
  is under 30% of the roster mean. Cannot distinguish genuine isolation from "this tool doesn't see their work" —
  both are disclosed.
- **`signalToNoise(P, today)`** — signal = events referenced by an active finding from `LEADOS.engine`; noise =
  everything else. Reuses the engineering SNR/decibel formula as a labeled metaphor, not a physical signal.

## What's real vs. heuristic vs. not implemented

- **Real, working code:** the event log (append-only, localStorage), the roster, Export/Reset/Wipe, the hash
  router, the Shannon entropy formula itself, and `LEADOS.engine` (6 rules, arbitrary thresholds, built only so
  `signalToNoise()` has real findings to reference).
- **Heuristic, labeled as such everywhere it appears:** the entropy interpretation bands, the mutual-information
  approximation, the bottleneck inference, and the SNR interpretation text.
- **Not implemented / explicitly out of scope:** Parts 2+ of the pt-L brief (not pasted into this task), and
  anything from the real `wbweve/Leados` repo's orphaned `src/lib/{core,intelligence,physics}.ts` files, which
  this session did not copy because they are not wired into that repo's own build and their origin (per their own
  in-file comments) is a prior, separate sandbox session, not the repository's real/shipped code.
