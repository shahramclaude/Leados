# ADR-0096: Registered Terminal Publication — the five unregistered terminals enter the differencing register

- **Status:** accepted (2026-11-05, Session 136, no schema bump)
- **Context:** ADR-0092 made the *release* the unit of disclosure: every published aggregate becomes a dated row in the differencing register and the whole series is audited as one integer system across days, seats and altitudes. ADR-0091 audits one table at one moment. But five terminals — `#/escalation`, `#/measurement`, `#/cadence`, `#/concordance`, `#/survival` — still applied their own per-table small-cell floor directly and never entered the register, so a *series* of their printed tables (two dates, two seats, parent vs child) was never audited. The roadmap listed this as a standing in-progress item.
- **Decision:**
  1. `#/escalation` and `#/cadence` declare disclosure manifests (`escalationRecords` + `escalationCommitments`; `cadenceForums` + `cadenceSessions`; both `classKey: 'unit'`, `adapterScoped`, `detailCeiling: 5`), so `planRelease` can build a span aggregate for them. `#/measurement`, `#/concordance` and `#/survival` already had manifests.
  2. A shared view, `app/views/publicationPanel.js`, is mounted on all five terminals (a "Publication register" tab, or a card on the tabless measurement page). It exposes the register's two reads — **Plan** (`differencesPlan`: what would publishing this module's aggregate right now determine, against every release already registered?) and **Publish** (`differencesPublish`: one dated release per module per day per seat; a second same-day publish is refused by construction) — and shows whether the module was published today from the operating seat.
  3. The terminal's own per-table floor is unchanged; the register only ever *adds* suppression. A determined value is reported as a coordinate and a proof, never as the number.
- **Altitudes served:** all five — a frontline lead can plan/publish their own span's aggregate; a director/VP/CEO reads registered series through `#/differencing`, and releases roll up to ancestors via the existing `rolls-up-to` spine.
- **Consequences:** the register report now carries these five routes, so their release series is audited by exact integer determinacy; the catalogue and the shell stay one-route-for-one-route (`RENDERER_ROUTES` updated). Cadence attribution follows the declared people keys (`ownerId` on sessions); `chairSeatId`/`attendeeIds` are not people keys and are noted as a known limit.
- **Rejected:** auto-publishing on every render (the register would fill with unaudited-pattern days and the same-day guard would refuse real publications); adding `chairSeatId` to the global `PEOPLE_KEYS` (workspace-wide attribution semantics change, out of scope); claiming differential privacy (exact integer determinacy over what this workspace published is the claim).
- **Verification:** `tests/app/terminal-publication.test.mjs` (5/5) — manifests for all five routes, plan builds for all five, publish writes exactly one row and a same-day second publish is refused without writing, cross-module same-day publish allowed, panel axe-clean. `disclosure-compiler` + `differencing` 52/52; lint, boundary (474 modules), links pass. Two failures in `operating-cadence`/`measurement` suites are pre-existing on the base commit (verified via stash).
