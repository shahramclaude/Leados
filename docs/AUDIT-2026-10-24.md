## 1. What actually exists

The original session characterized **four** competing application entry points below.
Its blanket “none was working” conclusion is not freshly verified in session 4:

1. **Root Vite entry** — `index.html` + `main.tsx` + `App.tsx` + `src/App.tsx`
   ("Quality & Governance Console"). `index.html` loads `/src/main.tsx`, which imports
   `./sections/Overview` etc. `vite`, `@vitejs/plugin-react` and `vite-plugin-singlefile` are
   **not in `package.json`**, so this entry point cannot build. Root `App.tsx` imports
   `./lib/store` — there is no `lib/` at the repository root. **[Broken — verified]**
2. **Next.js App Router app** — current inventory: 262 `page.tsx` files and 903 DB-importing
   files. **Correction:** `src/db/` exists; its client requires `DATABASE_URL`, and the root
   page runs a query and displays the PostgreSQL starter. Earlier absent-layer/build-failure
   assertions are not current proof. **[Current build/runtime: UNVERIFIED in session 4]**
3. **`public/index.html`** — a genuinely self-contained 1,230-line single-file console
   ("Strategic Consciousness, Decision Oracle, Knowledge Graph") with nine inline domain
   modules (rule engine, Bayesian beliefs, behavioural-econ detectors, flight risk, health
   score, strategic synthesis, decision oracle, knowledge graph, self-tests) and
   localStorage persistence. It was **rendering nothing** because of this comment:

   ```js
   /* ... the pasted brief's unverified T_T_*/G_L_* ... */
   ```

   The `*/` inside `T_T_*/` closed the block comment, so the rest of the file was parsed as
   code. A one-character-class fix (`T_T_* / G_L_*`) restored it. **[Fixed this session;
   now renders 5 routes with 0 console errors in jsdom]**
4. **`leados-cli.html`** — a terminal companion that talks to the console over
   `BroadcastChannel`. Loads in a browser; it is a curiosity, not a product surface.
   **[Partially verified: file is syntactically standalone; message loop not exercised]**

## 4. Position taken this session

The original session concluded that it should select a new canonical entry and recorded
that rewrite decision. **This historical rationale does not prove that incremental repair
of every legacy component was impossible**, especially given the corrected DB premise.
Session 4 preserves and incrementally improves the now-working canonical app. The original
session's actions were:

1. **Preserved** `public/index.html` and repaired its blocking syntax error (it is now a
   working read-only simulation sandbox, linked as such).
2. **Did not delete** the Next.js tree or the Vite files. They are left untouched and are
   explicitly documented as non-canonical. The earlier absent-schema/data-layer premise
   is withdrawn; current repair feasibility and build health require a fresh legacy audit
   and remain **[UNVERIFIED]**.
3. **Built the canonical application** at the repository root: `index.html` plus
   `app/**` ES modules, zero build step, zero dependencies, real user-entered data,
   versioned localStorage persistence, an append-oriented, capped event log, export/import, and a
   Node-runnable test suite covering the scoring and insight logic.
4. **Salvaged the domain thinking** from the console: findings carry rule IDs, evidence
   strings, explicit severity and confidence; the health score is a transparent weighted
   composite with per-dimension formulas; flight risk is a disclosed weighted composite.
   What changed is the *input*: every number now derives from data the leader entered.

See `docs/adr/0006-canonical-zero-build-app.md` for the decision record and
`ROADMAP.md` for the research inventory and the gap analysis that produced the build order.
